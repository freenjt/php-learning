Xdebug Observability Taxonomy & Modes

Xdebug 3 categorizes runtime instrumentation into distinct operational modes configured via `xdebug.mode` or `XDEBUG_MODE` environment variable.

Execution Tracing (`trace`)

Logs every function call, parameters, assignments, and return values to disk.

  • • xdebug_start_trace()
  • • xdebug_stop_trace()
  • • xdebug_get_tracefile_name()
Code Coverage (`coverage`)

Tracks executed lines, dead code, decision branches, and execution paths.

  • • xdebug_start_code_coverage()
  • • xdebug_get_code_coverage()
  • • xdebug_stop_code_coverage()
Step Debugging (`debug`)

Enables interactive DBGp protocol debugging and programmatic breakpoints.

  • • xdebug_break()
  • • xdebug_connect_to_client()
  • • xdebug_is_debugger_active()
Caller Introspection (`develop`)

Enhanced error reporting, var_dump overrides, and caller frame querying.

  • • xdebug_call_class()
  • • xdebug_call_function()
  • • xdebug_call_file() / _line()
Garbage & Memory Stats (`gcstats`)

Monitors memory allocation, GC runs, and high-precision monotone clock time.

  • • xdebug_start_gcstats()
  • • xdebug_memory_usage()
  • • xdebug_get_monotone_time()
Performance Profiling (`profile`)

Generates Cachegrind / Flamegraph output files for bottleneck analysis.

  • • xdebug.mode=profile
  • • xdebug_get_profiler_filename()
  • • xdebug_info('extension-flags')

Programmatic Execution Tracing

Dynamically control function call tracing at runtime using native PHP function calls.

Dynamic Trace Triggering 
<?php
// Requires XDEBUG_MODE=trace or xdebug.mode=trace

echo "Before trace...\n";

// Start recording trace to custom path or auto-generated filename
$traceFile = xdebug_start_trace('/tmp/custom_order_process');

// Execute target business logic to inspect
$orderService->processPayment($orderId);

// Stop recording trace
xdebug_stop_trace();

echo "Trace written to: " . xdebug_get_tracefile_name();
?>
Official xdebug.org Rule:

xdebug_start_trace() returns the trace file path on success, or false if tracing could not be started or if mode is not enabled!

Trace File Formats & Variable Telemetry Options

Configure how Xdebug logs function invocation parameters, assignments, and return values.

`xdebug.trace_format` Modes 
; 0 = Human Readable (time, memory, function call, location)
xdebug.trace_format = 0

; 1 = Machine Readable (Tab-separated format for automated parsing)
xdebug.trace_format = 1

; 2 = HTML Formatted Output (Visual browser inspect)
xdebug.trace_format = 2

Bitwise options passed to xdebug_start_trace($file, XDEBUG_TRACE_APPEND) allow appending to existing trace files or custom file patterns.

Deep Telemetry Collection 
; Collect variable assignments in trace files
xdebug.collect_assignments = 1

; Collect function return values in trace files
xdebug.collect_return = 1

; Configure compression if compiled in (GZip trace files)
xdebug.use_compression = 1

Enabling variable assignment tracking reveals exact state transformations at every line execution.

Programmatic Code Coverage Instrumentation

Measure code execution paths dynamically for custom test harnesses, automated benchmarks, or PHPUnit integration.

Capturing Coverage Programmatically 
<?php
// Requires xdebug.mode=coverage
xdebug_start_code_coverage(XDEBUG_CC_UNUSED | XDEBUG_CC_DEAD_CODE);

// Execute target code unit
runApplicationLogic();

// Retrieve line-by-line coverage matrix
$coverageData = xdebug_get_code_coverage();

xdebug_stop_code_coverage();

// Structure: [ '/path/file.php' => [ line_num => hit_status ] ]
var_dump($coverageData);
?>
Line Execution Status Codes:
  • 1 : Line was executed during run
  • -1 : Line is executable but was NOT hit
  • -2 : Dead code (unreachable line)
Coverage Analysis Bitflags
XDEBUG_CC_UNUSED

Scans code units to detect executable lines that were not hit, tagging them with status -1.

XDEBUG_CC_DEAD_CODE

Performs dead code analysis to find unreachable statements, tagging them with status -2.

XDEBUG_CC_BRANCH_CHECK

Enables decision branch analysis to track which control structure branches were evaluated.

XDEBUG_CC_PATH_CHECK

Enables full execution path analysis to evaluate all combinations of branch paths.

Code Coverage Filtering

Xdebug filtering allows restricting coverage analysis to specific source directories or namespaces, boosting execution speed by up to 2x during test suite execution. 

// Configured via php.ini or environment settings

    XDEBUG_FILTER_CODE_COVERAGE,
    XDEBUG_PATH_WHITELIST,
    [ __DIR__ . '/src/' ]
);

Programmatic Step Debugging & Breakpoint Control

Programmatically initiate interactive DBGp debugging sessions and emit breakpoints directly from PHP code.

Emit Programmatic Breakpoint 
<?php
// Emit a breakpoint to the attached IDE debug client
if ($unexpectedCondition) {
    // Halts execution in IDE as if file/line breakpoint was set
    $active = xdebug_break(); 
    
    if ($active) {
        echo "Debugger attached and session break hit!";
    }
}
?>

If xdebug.start_with_request=trigger is configured, xdebug_break() attempts to establish a new debugging session first.

CLI Queue Worker Reconnection 
<?php
// For long-running CLI queue workers (Introduced in Xdebug 3.1)
while ($job = $queue->getNextJob()) {
    if ($job->requiresDebugging()) {
        // Instructs Xdebug to retry connecting to IDE
        xdebug_connect_to_client();
        
        xdebug_break();
    }
    $job->execute();
}
?>

xdebug_connect_to_client() enables re-establishing IDE DBGp client connections on demand during long-lived process loops.

Lightweight Caller Introspection (`xdebug_call_*`)

Query call frame origins efficiently without the performance overhead of generating full backtraces.

Programmatic Caller Inspection 
class AuditLogger {
    public static function log(string $msg): void {
        // Retrieve caller information at stack depth 2
        $callerClass = xdebug_call_class(depth: 2);
        $callerFunc  = xdebug_call_function(depth: 2);
        $callerFile  = xdebug_call_file(depth: 2);
        $callerLine  = xdebug_call_line(depth: 2);

        echo "Log triggered by {$callerClass}::{$callerFunc} " .
             "at {$callerFile}:{$callerLine}\n";
    }
}

Default depth is 2 (grandparent frame of caller method).

Depth Argument Mapping
depth = 0 Call info of xdebug_call_* itself
depth = 1 Immediate calling method / function
depth = 2 (Default) Caller of the current function ("grandparent")
depth = N Ancestoral frame frame at level N

Returns null if frame does not exist, or false if frame has no class/function.

Call Stack Telemetry & Variable Capture

Programmatically inspect full stack frames, local variables, and thrown exception stack states.

Programmatic Stack Array Retrieval 
<?php
// Inspect call stack with local variables (Xdebug 3.3+)
$stack = xdebug_get_function_stack([
    'local_vars' => true
]);

// Inspect stack trace captured at exception throw time
try {
    throwException();
} catch (\Throwable $e) {
    $exceptionStack = xdebug_get_function_stack([
        'from_exception' => $e
    ]);
}
?>

High-Precision Timing API 
<?php
// Returns monotone time in seconds with microsecond resolution
$t0 = xdebug_get_monotone_time();

// Perform operations
heavyTask();

$elapsed = xdebug_get_monotone_time() - $t0;

echo "Task executed in {$elapsed} seconds\n";
echo "Current Memory: " . xdebug_memory_usage() . " bytes\n";
echo "Peak Memory: "    . xdebug_peak_memory_usage() . " bytes\n";
?>

Monotone time is immune to system clock drift and NTP adjustments.
