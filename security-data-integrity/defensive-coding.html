Core Pillars of Defensive PHP Development

Defensive programming assumes all input is malicious, state transitions can fail, and external systems are inherently unreliable.

1. Fail Fast & Strict Typing

Enable declare(strict_types=1); to prevent type coercion and catch type mismatches at execution start.

  • • Strict scalar & return types
  • • Rejection of implicit string/int coercion
  • • Immediate TypeError throwing
2. Never Trust Untrusted Input

Sanitize and validate every incoming value via filter_input() and filter_var() before processing.

  • • Reject unexpected input payloads
  • • Validate data types & ranges
  • • Escape HTML output with htmlspecialchars
3. State Immutability & Enums

Prevent unintended object mutations with readonly properties, classes, and typed backed Enums.

  • • Immutable Value Objects
  • • Strict type-safe state options
  • • Private constructor encapsulation
4. Null Safety & Coalescing

Eliminate NullPointer/Warning errors using the Nullsafe operator (?->) and Null Coalescing (??).

  • • Short-circuiting null checks
  • • Safe default fallback values
  • • Explicit nullable type hints (?string)
5. Explicit Boundary Exceptions

Throw domain-specific exceptions instead of returning ambiguous error codes or relying on silent failures.

  • • Custom SPL exception hierarchy
  • • Exhaustive try-catch-finally blocks
  • • Catching engine Throwable
6. Safe Database & File Ops

Protect against SQL injection via PDO prepared statements and sanitize file paths using realpath().

  • • Parameterized query binding
  • • Directory traversal prevention
  • • Atomic file write locks

Strict Types & Return Type Guarantees

By default, PHP coercively casts types. Enabling `declare(strict_types=1)` forces strict scalar type checking for caller and callee.

Modern PHP 8.2+ Defensive Type System 
<?php
declare(strict_types=1); // Mandatory per-file directive

namespace App\Defensive;

class FinancialCalculator {
    /**
     * Defensive function using Union, Intersection & Never types
     */
    public function processTransaction(
        int|float $amount,
        string $currency,
        \Stringable&\Countable $accountDetails
    ): float {
        if ($amount <= 0) {
            $this->haltProcess("Transaction amount must be positive");
        }

        return (float)$amount;
    }

    private function haltProcess(string $reason): never {
        throw new \InvalidArgumentException($reason);
    }
}
php.net Standard:

Strict typing applies to function calls made from within the file with strict typing enabled, throwing a \TypeError on mismatches.

Coercive vs Strict Typing Behavior
Without strict_types=1 (Coercive) 
function calculate(int $x): int { return $x * 2; }
calculate("100 apples"); // Returns 200 or raises deprecation!
calculate(45.99);        // Silently truncates to 45!
With declare(strict_types=1) (Defensive) 
declare(strict_types=1);
calculate("100 apples"); // Throws TypeError immediately!
calculate(45.99);        // Throws TypeError immediately!

Input Sanitization & Filtering (`filter_var`, `filter_input`)

Never trust `$_GET`, `$_POST`, or `$_COOKIE`. Use PHP's built-in Filter extension for robust data validation and sanitization.

Defensive Filtering Implementation 
<?php
declare(strict_types=1);

// 1. Safely inspect HTTP Superglobal via filter_input
$email = filter_input(
    INPUT_POST, 
    'user_email', 
    FILTER_VALIDATE_EMAIL
);

if ($email === false || $email === null) {
    throw new \InvalidArgumentException("Invalid or missing email address.");
}

// 2. Validate Integer with Range Constraints
$age = filter_var($rawAge, FILTER_VALIDATE_INT, [
    'options' => [
        'min_range' => 18,
        'max_range' => 120
    ]
]);

if ($age === false) {
    throw new \OutOfRangeException("Age must be between 18 and 120.");
}

Source: php.net/book.filter

Essential Native Filters (php.net)
FILTER_VALIDATE_EMAIL Validates RFC 822 email format strictly without custom regex bugs.
FILTER_VALIDATE_URL Validates scheme, host, and path components of web addresses.
FILTER_VALIDATE_IP Supports flags like FILTER_FLAG_NO_PRIV_RANGE to block private IPs.
htmlspecialchars() Converts special characters to HTML entities with ENT_QUOTES | ENT_SUBSTITUTE | ENT_HTML5.

Defensive Null Safety & Defensive Operators

Eliminate nested null checks and `Undefined array key` warnings with short-circuiting nullsafe operators (`?->`), null coalescing (`??`), and `??=`.

Nullsafe Chain & Null Coalescing 
<?php
declare(strict_types=1);

// 1. Short-circuiting Nullsafe Operator (?->)
// If $user, getProfile(), or getAddress() is null, entire chain evaluates to null without throwing Warning
$country = $user?->getProfile()?->getAddress()?->country;

// 2. Safe Fallback with Null Coalescing Operator (??)
$displayCountry = $country ?? 'Unknown Region';

// 3. Null Coalescing Assignment Operator (??=)
// Assigns value ONLY if $config['timeout'] is null or unset
$config['timeout'] ??= 30;

Source: php.net/language.operators.nullsafe

Code Refactoring Comparison
Fragile Pre-PHP 8 Approach 
$country = 'Unknown Region';
if ($user !== null) {
    $profile = $user->getProfile();
    if ($profile !== null) {
        $address = $profile->getAddress();
        if ($address !== null && isset($address->country)) {
            $country = $address->country;
        }
    }
}
Modern PHP 8.x Defensive One-Liner 
$country = $user?->getProfile()?->getAddress()?->country ?? 'Unknown Region';

Defensive Exception Handling & Throwable Boundaries

Catch `\Throwable` at execution boundaries to intercept both engine `\Error` instances and domain `\Exception` occurrences gracefully.

Exception Hierarchy & Finally Block 
<?php
declare(strict_types=1);

namespace App\Exception;

// Domain Exception Contract
class PaymentFailedException extends \RuntimeException {}

class PaymentGateway {
    public function execute(float $amount): void {
        try {
            // Risky operation
            $this->chargeExternalApi($amount);
        } catch (\TypeError|\ValueError $e) {
            // Catch native language engine errors
            throw new PaymentFailedException("Invalid payload structure", 0, $e);
        } catch (\Throwable $e) {
            // Catch ANY uncaught exception or engine Error
            \error_log("Critical failure: " . $e->getMessage());
            throw new PaymentFailedException("Payment processing failed safely", 0, $e);
        } finally {
            // Guaranteed cleanup boundary
            $this->closeApiConnection();
        }
    }
}

State Immutability & Backed Enums (`readonly`)

Prevent unexpected state mutation across application layers using PHP 8.2 `readonly` classes and Backed Enums.

Immutable Value Object & Backed Enum 
<?php
declare(strict_types=1);

namespace App\Domain;

// 1. Backed Enum for Type-Safe Fixed States
enum AccountStatus: string {
    case Active = 'active';
    case Suspended = 'suspended';
    case Closed = 'closed';
}

// 2. Readonly Class (All properties implicitly readonly & unmodifiable after construction)
final readonly class UserAccount {
    public function __construct(
        public int $id,
        public string $email,
        public AccountStatus $status
    ) {}
}

$account = new UserAccount(101, 'user@domain.com', AccountStatus::Active);
// $account->email = 'hacked@domain.com'; // Throws Error: Cannot modify readonly property!

Source: php.net/readonly-classes

Defensive Immutability Benefits
1. Thread-Safe State Integrity

Once instantiated, readonly objects guarantee that properties cannot be altered by side-effect functions or external modules.

2. Elimination of Invalid States

Enums (AccountStatus::from($value)) automatically throw a \ValueError if an invalid string status is provided.

3. Predictable Hashability & Equality

Immutable value objects can be safely passed across domain boundaries without defensive deep cloning.

Defensive Database Operations with PDO

Eliminate SQL Injection completely by configuring PDO to throw exceptions and using strictly typed parameter binding.

Hardened PDO Instantiation & Query 
<?php
declare(strict_types=1);

$options = [
    // Force PDO to throw PDOException on failure
    \PDO::ATTR_ERRMODE            => \PDO::ERRMODE_EXCEPTION,
    // Fetch associative arrays by default
    \PDO::ATTR_DEFAULT_FETCH_MODE => \PDO::FETCH_ASSOC,
    // Disable emulated prepares to force native database prepared statements
    \PDO::ATTR_EMULATE_PREPARES   => false,
];

$pdo = new \PDO($dsn, $username, $password, $options);

// Defensive Parameterized Binding
$stmt = $pdo->prepare('SELECT id, name FROM users WHERE role = :role AND points >= :points');
$stmt->bindValue(':role', 'admin', \PDO::PARAM_STR);
$stmt->bindValue(':points', 500, \PDO::PARAM_INT);
$stmt->execute();

$results = $stmt->fetchAll();

Source: php.net/pdo.setattribute

Why Emulated Prepares Must Be Disabled
ATTR_EMULATE_PREPARES = true (Risky)

PHP simulates prepared statements internally by concatenating escaped strings before sending to MySQL. Multibyte character set vulnerabilities (e.g., GBK charset) can bypass string escaping.

ATTR_EMULATE_PREPARES = false (Defensive)

The query structure and data values are transmitted in separate binary protocols to the database server. Data is NEVER executed as SQL instructions.

Pre-conditions, Post-conditions & Assertions (`assert`)

Use `assert()` to verify internal program invariants during development and enforce architectural contracts.

Programmatic Invariant Validation 
<?php
declare(strict_types=1);

namespace App\Service;

class InventoryService {
    public function deductStock(int $itemId, int $quantity): int {
        // 1. Pre-condition Assertions
        assert($quantity > 0, new \InvalidArgumentException("Deduction quantity must be positive"));

        $currentStock = $this->fetchStock($itemId);
        
        // 2. Invariant Check
        assert($currentStock >= $quantity, new \UnderflowException("Insufficient stock available"));

        $newStock = $currentStock - $quantity;

        // 3. Post-condition Assertion
        assert($newStock >= 0, new \LogicException("Post-deduction stock balance cannot be negative"));

        return $newStock;
    }
}

Defensive Cryptography & Secure Filesystem Access

Harden file uploads and password handling using `password_hash()`, timing-attack safe `hash_equals()`, and `realpath()`.

Timing-Safe Password Hashing 
<?php
declare(strict_types=1);

// 1. Password Hashing using Argon2id or Bcrypt
$hash = \password_hash($rawPassword, PASSWORD_ARGON2ID);

if (\password_verify($userInputPassword, $hash)) {
    // 2. Defensive Hash Rehash Check
    if (\password_needs_rehash($hash, PASSWORD_ARGON2ID)) {
        $newHash = \password_hash($userInputPassword, PASSWORD_ARGON2ID);
        $userRepository->updateHash($userId, $newHash);
    }
}

// 3. Timing-Attack Safe Comparison for Tokens
$isTokenValid = \hash_equals($knownSecretToken, $userSubmittedToken);

Directory Traversal Defense (`realpath`) 
<?php
declare(strict_types=1);

function safeFileRead(string $userFilename, string $baseDir): string {
    // Canonicalize path to resolve symlinks and relative '../'
    $realBase = \realpath($baseDir);
    $targetPath = \realpath($baseDir . '/' . $userFilename);

    // Verify target path exists AND stays inside base directory boundary
    if ($targetPath === false || \strncmp($targetPath, $realBase, \strlen($realBase)) !== 0) {
        throw new \SecurityException("Path traversal attempt detected!");
    }

    return \file_get_contents($targetPath);
}
