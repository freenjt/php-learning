What is Dependency Injection in PHP?

Dependency Injection (DI) is an OOP architectural pattern where a class receives its required object dependencies from the outside rather than constructing them internally.

Inversion of Control (IoC)

Control over instance creation is inverted. The client class no longer owns object creation lifecycle.

  • • Eliminates hardcoded new keywords
  • • Decouples concrete class names
  • • Centralizes instantiation logic
Unit Testability

Injecting dependencies allows passing Mock or Stub objects during automated PHPUnit testing.

  • • Pass Mock objects without DB calls
  • • Fast isolated unit tests
  • • Deterministic state assertions
Interface Decoupling

Type-hinting interfaces (php.net/language.oop5.interfaces) allows swapping implementations effortlessly.

  • • Type hint interface parameters
  • • Polymorphic substitution
  • • Adheres to DIP (Dependency Inversion)
Constructor Promotion

PHP 8.0+ constructor property promotion (php.net/language.oop5.decls) eliminates injection boilerplate.

  • • Combine parameter & property declaration
  • • Reduced syntax redundancy
  • • Seamless readonly property pairing
Immutable DI (Readonly)

PHP 8.1+ readonly properties & 8.2+ readonly class protect injected services from modification.

  • • Single initialization guarantee
  • • Prevents runtime tampering
  • • Thread-safe immutability semantics
Reflection Autowiring

PHP Reflection API (php.net/book.reflection) enables containers to automatically resolve dependency trees.

  • • Inspect constructor parameters
  • • Recursive class instantiation
  • • Zero-configuration service graphs

Tight Coupling vs. Dependency Injection

Compare hardcoded concrete instantiations against explicit interface constructor injection in PHP 8.x.

Tightly Coupled (Anti-Pattern) 
<?php
declare(strict_types=1);

class MySQLConnection {
    public function connect(): void { /* DB Connect */ }
}

class UserNotifier {
    private MySQLConnection $db;

    public function __construct() {
        // BAD: Hardcoded 'new' instantiates concrete low-level class!
        // Cannot swap database driver or inject mock for testing!
        $this->db = new MySQLConnection();
    }

    public function notify(int $userId): void {
        $this->db->connect();
    }
}

Cannot mock `MySQLConnection` during unit tests without modifying source code!

Decoupled via Constructor DI 
<?php
declare(strict_types=1);

interface DatabaseConnectionInterface {
    public function connect(): void;
}

// PHP 8.2+ Readonly Class with Constructor Promotion
readonly class UserNotifier {
    public function __construct(
        private DatabaseConnectionInterface $dbConnection
    ) {}

    public function notify(int $userId): void {
        $this->dbConnection->connect();
    }
}

Inject any implementation (MySQL, PostgreSQL, InMemory Mock) seamlessly!

Constructor Promotion & Readonly Properties

PHP 8.0 introduced Constructor Property Promotion and PHP 8.1/8.2 added Readonly mechanics to streamline DI.

Legacy PHP 7.x DI Boilerplate 
<?php
class OrderProcessor {
    private LoggerInterface $logger;
    private PaymentGatewayInterface $gateway;

    public function __construct(
        LoggerInterface $logger,
        PaymentGatewayInterface $gateway
    ) {
        $this->logger = $logger;
        $this->gateway = $gateway;
    }
}

Requires 3 repetitions per dependency (Property, Parameter, Assignment).

Modern PHP 8.2+ Readonly DI Class 
<?php
declare(strict_types=1);

// PHP 8.2+ Readonly class enforces immutability across all properties!
readonly class OrderProcessor {
    public function __construct(
        private LoggerInterface $logger,
        private PaymentGatewayInterface $gateway
    ) {}
}

Concise, immutable, and fully type-safe. Perfect for DI service classes!

Types of Dependency Injection in PHP

Understand when to use Constructor Injection, Setter Method Injection, or Method Injection in PHP applications.

Constructor Injection

Pass mandatory dependencies directly during object instantiation in __construct().

readonly class InvoiceService {
    public function __construct(
        private MailerInterface $mailer
    ) {}
}
Best Practice (Mandatory)
Setter Injection

Inject optional dependencies via dedicated setter methods after construction.

class CacheableReport {
    private ?CacheInterface $cache = null;

    public function setCache(CacheInterface $c): void {
        $this->cache = $c;
    }
}
Optional / Fallback Dependencies
Method Action Injection

Inject dependencies directly into specific action methods (e.g. Controller actions).

class UserController {
    public function show(
        int $id,
        UserRepositoryInterface $repo
    ): User {
        return $repo->find($id);
    }
}
Action Scope / Controller Dispatch

Interfaces as Contracts for DI

PHP Object Interfaces (php.net/language.oop5.interfaces) allow declaring method contracts without concrete implementations.

<?php
declare(strict_types=1);

namespace App\Contracts;

// 1. Declare contract interface
interface PaymentGatewayInterface {
    public function charge(float $amount): bool;
}

// 2. Concrete Strategy A
class StripeGateway implements PaymentGatewayInterface {
    public function charge(float $amount): bool {
        // Stripe API HTTP Request
        return true;
    }
}

// 3. Concrete Strategy B
class PayPalGateway implements PaymentGatewayInterface {
    public function charge(float $amount): bool {
        // PayPal SDK Call
        return true;
    }
}

// 4. High-level class depends ONLY on PaymentGatewayInterface abstraction!
readonly class CheckoutProcessor {
    public function __construct(
        private PaymentGatewayInterface $gateway
    ) {}

    public function processOrder(float $total): void {
        if ($this->gateway->charge($total)) {
            echo "Order completed successfully!\n";
        }
    }
}
Contract Guarantee: `CheckoutProcessor` doesn't care whether `StripeGateway` or `PayPalGateway` is supplied, as long as it adheres to `PaymentGatewayInterface`.

Type Variance in PHP 8.x DI

Covariant return types and Contravariant argument types (php.net/language.oop5.variance) ensure Liskov Substitution Principle (LSP) safety in DI containers.

Covariant Return Types (PHP 7.4+)

A factory or factory dependency method can return a narrower (more specific) subclass.

abstract class AbstractResponse {}
class JsonResponse extends AbstractResponse {}

interface ResponseFactoryInterface {
    public function create(): AbstractResponse;
}

class ApiFactory implements ResponseFactoryInterface {
    // Covariant Return: Returns specific JsonResponse!
    public function create(): JsonResponse {
        return new JsonResponse();
    }
}
Contravariant Parameters (PHP 7.4+)

A child method argument can accept a wider (more general) supertype.

class AdminUser extends User {}

interface AdminHandlerInterface {
    public function handle(AdminUser $admin): void;
}

class GeneralUserHandler implements AdminHandlerInterface {
    // Contravariant Parameter: Accepts general User superclass!
    public function handle(User $user): void {
        // Process user
    }
}

PHP Reflection API & Autowiring

How modern PHP DI Containers use ReflectionClass and ReflectionNamedType (php.net/book.reflection) to automatically resolve object graphs.

<?php
declare(strict_types=1);

class Container {
    private array $bindings = [];

    public function bind(string $abstract, string $concrete): void {
        $this->bindings[$abstract] = $concrete;
    }

    public function get(string $className): object {
        $target = $this->bindings[$className] ?? $className;
        
        // 1. Inspect class via Reflection
        $reflector = new ReflectionClass($target);
        $constructor = $reflector->getConstructor();

        if ($constructor === null) {
            return new $target();
        }

        // 2. Resolve constructor parameters recursively
        $dependencies = [];
        foreach ($constructor->getParameters() as $param) {
            $type = $param->getType();
            
            if ($type instanceof ReflectionNamedType && !$type->isBuiltin()) {
                // Recursively instantiate dependency!
                $dependencies[] = $this->get($type->getName());
            }
        }

        return $reflector->newInstanceArgs($dependencies);
    }
}
Autowiring in action: The container inspects parameter type-hints at runtime using Reflection and injects required instances automatically!
