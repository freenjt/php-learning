S - Single Responsibility Principle (SRP)

"A class should have one, and only one, reason to change." Separate domain logic, persistence, and notifications into specialized units.

SRP Violation (God Object) 
class UserService {
    // VIOLATION: Handles business logic AND DB query AND Email sending!
    public function registerUser(array $data): void {
        // 1. Business Validation
        if (empty($data['email'])) throw new Exception('Invalid email');

        // 2. Database Persistence Logic
        $pdo = new PDO('mysql:host=localhost;dbname=app', 'root', '');
        $stmt = $pdo->prepare('INSERT INTO users VALUES (...)');
        $stmt->execute($data);

        // 3. Email Notification Logic
        $headers = 'From: no-reply@app.com';
        mail($data['email'], 'Welcome!', 'Hello...', $headers);
    }
}

Changes to DB drivers, mailers, or validation break the same class!

Refactored SRP Compliant Architecture 
// 1. Single Responsibility: Orchestrator
readonly class UserRegistrationService {
    public function __construct(
        private UserRepositoryInterface $repository,
        private MailerInterface $mailer
    ) {}

    public function register(User $user): void {
        $this->repository->save($user);
        $this->mailer->sendWelcomeEmail($user);
    }
}

// 2. Single Responsibility: Persistence
class UserRepository implements UserRepositoryInterface {
    public function save(User $user): void { /* DB Logic */ }
}

// 3. Single Responsibility: Email Delivery
class UserMailer implements MailerInterface {
    public function sendWelcomeEmail(User $user): void { /* Mail Logic */ }
}

High cohesion, isolated responsibilities, easily testable.

O - Open/Closed Principle (OCP)

"Software entities should be open for extension, but closed for modification." Extend behavior using strategy interfaces instead of adding conditional switch/if statements.

OCP Violation (Conditional Cascade) 
class DiscountCalculator {
    // VIOLATION: Adding a new customer type forces modifying this method!
    public function calculate(string $customerType, float $price): float {
        if ($customerType === 'regular') {
            return $price * 0.95;
        } elseif ($customerType === 'vip') {
            return $price * 0.80;
        } elseif ($customerType === 'employee') { // Added new type = modified code!
            return $price * 0.50;
        }
        return $price;
    }
}

Modifying existing classes risks introducing regressions into existing workflows.

Polymorphic Strategy Pattern 
interface DiscountStrategyInterface {
    public function applyDiscount(float $price): float;
}

class VipDiscount implements DiscountStrategyInterface {
    public function applyDiscount(float $price): float => $price * 0.80;
}

class EmployeeDiscount implements DiscountStrategyInterface {
    public function applyDiscount(float $price): float => $price * 0.50;
}

// Closed for modification, open for extension by injecting new strategy classes!
readonly class DiscountProcessor {
    public function process(DiscountStrategyInterface $strategy, float $price): float {
        return $strategy->applyDiscount($price);
    }
}

Add new strategies by declaring new classes without editing tested core logic!

L - Liskov Substitution Principle (LSP)

"Subtypes must be substitutable for their base types without altering system correctness." Guaranteed via covariant returns, contravariant parameters, and pre/postconditions.

LSP Violation (Contract Exception / Precondition) 
class FileStorage {
    public function write(string $filename, string $content): void {
        file_put_contents($filename, $content);
    }
}

class ReadOnlyStorage extends FileStorage {
    // VIOLATION: Throws exception on valid base class interface!
    // Cannot substitute ReadOnlyStorage where FileStorage is expected.
    public function write(string $filename, string $content): void {
        throw new LogicException("Cannot write to read-only storage!");
    }
}

Subtype breaks consumer expectations by throwing unexpected exceptions.

Type Safe Covariance (PHP 8.0+) 
abstract class Animal {}
class Dog extends Animal {}

interface AnimalShelter {
    public function adopt(): Animal; // Base interface returns Animal
}

class DogShelter implements AnimalShelter {
    // Covariant Return Type: PHP allows returning more specific subtype (Dog)!
    public function adopt(): Dog {
        return new Dog();
    }
}

function processShelter(AnimalShelter $shelter): void {
    $animal = $shelter->adopt(); // Guaranteed to return an Animal or subclass!
}

PHP engine enforces type covariance at compile time (`php.net/language.oop5.variance`).

I - Interface Segregation Principle (ISP)

"Clients should not be forced to depend upon interfaces that they do not use." Prefer multiple small, targeted interfaces over monolithic ones.

Fat Monolithic Interface 
interface WorkerInterface {
    public function work(): void;
    public function eat(): void;
    public function sleep(): void;
}

class RobotWorker implements WorkerInterface {
    public function work(): void { /* Working */ }

    // VIOLATION: Robots don't eat or sleep, forced to implement dummy methods!
    public function eat(): void { throw new UnsupportedException(); }
    public function sleep(): void { throw new UnsupportedException(); }
}

Forces dummy implementations and pollutes public interface contracts.

Segregated Granular Interfaces 
interface WorkableInterface {
    public function work(): void;
}

interface FeedableInterface {
    public function eat(): void;
}

// Robots implement ONLY what they can perform!
class RobotWorker implements WorkableInterface {
    public function work(): void { /* Assemble parts */ }
}

// Human workers implement multiple composed interfaces
class HumanWorker implements WorkableInterface, FeedableInterface {
    public function work(): void { /* Office work */ }
    public function eat(): void { /* Lunch break */ }
}

Clean interface composition and flexible component dependencies.

D - Dependency Inversion Principle (DIP)

"High-level modules should not depend on low-level modules. Both should depend on abstractions." Rely on interface contracts rather than concrete class names.

Tightly Coupled Concrete Class 
class MySQLConnection {
    public function connect(): void { /* MySQL driver setup */ }
}

class PasswordHasher {
    private MySQLConnection $db;

    public function __construct() {
        // VIOLATION: Hardcoded instantiation of concrete low-level class!
        $this->db = new MySQLConnection();
    }
}

Tight coupling prevents switching databases or injecting test doubles/mocks.

Abstraction Inversion via Constructor Injection 
interface DatabaseConnectionInterface {
    public function query(string $sql): array;
}

class PostgreSQLConnection implements DatabaseConnectionInterface {
    public function query(string $sql): array { return []; }
}

readonly class UserNotifier {
    // Inject abstraction interface instead of concrete instance!
    public function __construct(
        private DatabaseConnectionInterface $dbConnection
    ) {}

    public function notify(int $userId): void {
        $data = $this->dbConnection->query("SELECT * FROM users...");
    }
}

Decoupled architecture. Swap PostgreSQL, MySQL, or InMemory Mocks seamlessly!

Modern PHP 8.x Mechanics for SOLID

How modern PHP features—Constructor Promotion, Enums, Readonly Classes, First-Class Callables—simplify SOLID patterns.

Readonly Classes (PHP 8.2+) 
// Enforces immutability across ALL properties automatically!
readonly class OrderInvoiceService {
    public function __construct(
        private InvoiceCalculatorInterface $calculator,
        private PdfGeneratorInterface $pdfGenerator,
        private EventDispatcherInterface $events
    ) {}

    public function generateInvoice(Order $order): Invoice {
        $pdf = $this->pdfGenerator->render($this->calculator->calculate($order));
        $this->events->dispatch(new InvoiceCreatedEvent($order));
        return new Invoice($pdf);
    }
}

Eliminates 80% boilerplate code while guaranteeing DIP injection.

Enum Strategy Realization (PHP 8.1+) 
interface StatusHandlerInterface {
    public function getLabel(): string;
}

// PHP Enums can implement interfaces to provide lightweight OCP strategies!
enum OrderStatus: string implements StatusHandlerInterface {
    case Pending = 'pending';
    case Completed = 'completed';
    case Canceled = 'canceled';

    public function getLabel(): string => match($this) {
        self::Pending => 'Order is awaiting payment',
        self::Completed => 'Order fulfilled successfully',
        self::Canceled => 'Order was terminated',
    };
}

Type-safe value enumeration enforcing interface compliance (`php.net/language.types.enumerations`).
