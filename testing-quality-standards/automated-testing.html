The official PHP documentation establishes 6 primary pillars for programmatic test execution and engine verification.

The Official PHPT File Architecture

PHPT is PHP's core declarative test structure for engine regression testing, extension verification, and core bug fixes.

Standard `.phpt` Anatomy 
--TEST--
Core string transformation and formatting test
--SKIPIF--
<?php if (!extension_loaded('mbstring')) die('skip mbstring extension unavailable'); ?>
--INI--
zend.assertions=1
assert.exception=1
--FILE--
<?php
$input = "php automated testing";
$formatted = ucwords($input);
var_dump($formatted);
assert(is_string($formatted));
?>
--EXPECTF--
string(21) "Php Automated Testing"
Mandatory Rule:

Every `.phpt` file MUST contain at least --TEST--, --FILE--, and one expectation section (--EXPECT--, --EXPECTF--, or --EXPECTREGEX--).

Core PHPT Section Directives
Section Tag Purpose
--TEST-- One-line title description of the test case.
--SKIPIF-- PHP code that calls die("skip...") to bypass running.
--INI-- Custom php.ini directives required for execution.
--FILE-- The main executable PHP code payload.
--EXPECTF-- Expected output with format wildcards (%s, %d, %f).
--CLEAN-- Cleanup script executed after test completion (removes temp files).

Reference: qa.php.net/write-test.php

Execution Pipeline of `run-tests.php`

The native PHP CLI test runner manages process isolation, CLI argument passing, output diffing, and environment cleanup.

Generated Test Artifacts on Failure

When a test fails under run-tests.php, the harness generates isolated files alongside the source test:

  • test.php: Extracted code from --FILE-- executed by the runner.
  • test.out: Raw string output received from actual PHP stdout.
  • test.exp: Compiled expected output pattern from --EXPECT--.
  • test.diff: Unified line-by-line diff comparing actual vs expected output.
CLI Execution: php run-tests.php -p /usr/bin/php tests/basic/

Native Assertions & The `zend.assertions` Directives

PHP provides built-in assertions via `assert()` with zero-cost production bypass capabilities configured at compile time.

Modern `assert()` Usage (PHP 8+) 
// Simple expression assertion
assert($calculatedTotal >= 0, "Total amount cannot be negative");

// Custom exception throwing assertion
assert(
    $user->hasPermission('admin'),
    new \DomainException("User missing required test role")
);

// Programmatic type verification
function processItem(mixed $item): void {
    assert(is_object($item) || is_array($item), "Invalid item container");
}

Since PHP 8.0, string code evaluation inside assert() has been removed.

`zend.assertions` INI Modes
Value Mode Engine Behavior
1 Development Generates opcode and executes assertions at runtime.
0 Testing Bypass Generates opcode but skips execution dynamically at runtime.
-1 Production (Zero-Cost) Completely strips code generation during compilation! Zero performance cost.
Direct Exception Switch:

assert.exception = 1 forces failed assertions to throw an instance of \AssertionError.

`AssertionError` Handling vs. Assertion Callbacks

Understanding exception dispatching versus legacy callback registration during test failures.

Modern `AssertionError` Flow 
ini_set('zend.assertions', 1);
ini_set('assert.exception', 1);

try {
    $actual = 15;
    $expected = 20;
    assert($actual === $expected, "Value $actual does not equal $expected");
} catch (\AssertionError $e) {
    echo "Caught Test Failure: " . $e->getMessage() . "\n";
    echo "File: " . $e->getFile() . " Line: " . $e->getLine();
}

Recommended for modern programmatic test harnesses and custom assertion suites.

Legacy Callback Handler 
ini_set('zend.assertions', 1);
ini_set('assert.exception', 0); // Warning / Callback mode

assert_options(ASSERT_CALLBACK, function(
    string $file,
    int $line,
    ?string $code,
    ?string $desc = null
): void {
    echo "Assertion failed at {$file}:{$line}: {$desc}\n";
});

assert(2 + 2 === 5, "Math sanity failure");

Note: assert_options() is deprecated in PHP 8.3 and planned for removal.

Meta-Testing via Reflection API

Programmatically inspect private state, verify return type contracts, and bypass accessibility rules during test assertions.

Inspecting Non-Public State 
class OrderService {
    private string $internalStatus = 'draft';
}

$service = new OrderService();

// Programmatically inspect private property for assertion
$ref = new \ReflectionClass($service);
$property = $ref->getProperty('internalStatus');
$property->setAccessible(true); // Accessible in PHP < 8.1 / auto in 8.1+

$value = $property->getValue($service);
assert($value === 'draft', "Initial status must be draft");

Source: php.net/reflectionproperty.setaccessible

Signature Contract Assertions 
// Asserting interface or return type rules programmatically
$refMethod = new \ReflectionMethod(PaymentGateway::class, 'process');

// Verify return type is declared and allows string
assert($refMethod->hasReturnType(), "Method must declare return type");
$returnType = $refMethod->getReturnType();

assert($returnType->getName() === 'bool', "Must return boolean");
assert(!$returnType->allowsNull(), "Return type cannot be nullable");

Enforces architectural conventions programmatically within test runners.

Mocks, Stubs & Scope Re-Binding (`Closure::bind`)

Leveraging core OOP primitives: Anonymous Classes, Magic Interceptors, and Closure context manipulation for test isolation.

Anonymous Class Stubbing 
interface LoggerInterface {
    public function log(string $msg): void;
}

// Inline mock object without heavy external frameworks
$mockLogger = new class implements LoggerInterface {
    public array $logs = [];
    public function log(string $msg): void {
        $this->logs[] = $msg;
    }
};

$processor = new OrderProcessor($mockLogger);
$processor->execute();

assert(count($mockLogger->logs) === 1, "Expected 1 log entry");

Lightweight native mocking using PHP 7.0+ anonymous classes.

Dynamic Scope Injection (`Closure::bind`) 
class PrivateStateContainer {
    private int $secretCounter = 42;
}

$container = new PrivateStateContainer();

// Re-bind closure scope to access private variables without altering code
$extractor = Closure::bind(function(PrivateStateContainer $c) {
    return $c->secretCounter;
}, null, PrivateStateContainer::class);

assert($extractor($container) === 42);

Source: php.net/closure.bind

Attributes as Test Metadata (PHP 8.0+)

Using native `#[Attribute]` tags to declare test methods, data providers, and execution requirements programmatically.

Defining Custom Test Attributes 
#[Attribute(Attribute::TARGET_METHOD)]
class Test {}

#[Attribute(Attribute::TARGET_METHOD)]
class DataProvider {
    public function __construct(public string $methodName) {}
}

class UserTest {
    #[Test]
    #[DataProvider('provideUserAge')]
    public function testAgeValidation(int $age, bool $expected): void {
        assert((new User($age))->isValid() === $expected);
    }
}

Replaces legacy docblock annotations (@test) with structured engine attributes.

Programmatic Attribute Test Discovery 
$refClass = new ReflectionClass(UserTest::class);

foreach ($refClass->getMethods() as $method) {
    // Check if method carries #[Test] attribute
    $attributes = $method->getAttributes(Test::class);
    
    if (!empty($attributes)) {
        echo "Discovered Test Method: " . $method->getName() . "\n";
        // Instantiate and execute test...
    }
}

Code Coverage via Bundled PHPDBG Engine SAPI

PHP includes a built-in debugging SAPI (PHPDBG) capable of tracking line execution coverage programmatically.

Programmatic PHPDBG Coverage API 
// Start op-line log recording
phpdbg_start_oplog();

// Execute application code during test run
$calculator = new Calculator();
$result = $calculator->add(10, 20);

// Retrieve executed lines for the current file
$executedLines = phpdbg_get_executable_lines();
$oplog = phpdbg_end_oplog();

// Programmatically calculate percentage coverage
$executedCount = count($oplog[__FILE__] ?? []);
$totalCount = count($executedLines);
$coveragePct = ($executedCount / $totalCount) * 100;

echo "Line Coverage: {$coveragePct}%\n";

Source: php.net/book.phpdbg
