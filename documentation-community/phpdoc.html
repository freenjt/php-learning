Anatomy & Structure of a PHPDoc DocBlock

A DocBlock is a combination of a DocComment container and PHPDoc Domain Specific Language (DSL) consisting of Summary, Description, and Tags.

DocBlock Standard Form 
/**
 * Summary: One-liner describing the purpose.
 *
 * Description: Detailed explanation supporting Markdown
 * formatting, inline tags like {@link https://example.com},
 * and multi-line explanations of algorithms or structures.
 *
 * @author  Jane Doe <jane@example.com>
 * @param   string $identifier The entity lookup ID.
 * @return  \App\Domain\User   The resolved entity object.
 * @throws  \InvalidArgumentException If ID format is invalid.
 */
public function findUser(string $identifier): User
Mandatory Delimitation:

DocComments MUST start with /** (two asterisks) and end with */. Standard comments /* ... */ or // are ignored by phpDocumentor and Reflection API (getDocComment()).

3 Core Sections of a DocBlock
1. Summary (Short Description)

A high-level summary ending with a full stop (.) followed by a newline OR terminated by two consecutive newlines. Plain text only (no Markdown or tags).

2. Description (Long Description)

Provides granular details, algorithms, or code samples. Supports Markdown styling and inline tags enclosed in braces like {@link} or {@inheritDoc}.

3. Tags Block

A series of descriptors starting with an @ symbol on a new line (e.g. @param, @return). Supplies metadata for IDEs and generators.

Reference: docs.phpdoc.org/guide/references/phpdoc/basic-syntax.html

Structural Elements & DocBlock Association

PHPDoc automatically binds a DocBlock to the single Structural Element that immediately follows it in code.

File-Level DocBlock

Must be the FIRST DocBlock in a file, preceding any code except declare statements.

/**
 * File Overview.
 * @package App\Core
 */
Class, Interface & Trait

Documents object definitions, interfaces, traits, or PHP 8.1+ Enums.

/**
 * User Repository Service.
 */
class UserRepository {}
Functions & Methods

Documents signature parameters, return values, and thrown exceptions.

/**
 * @param int $id
 */
function getUser($id) {}
Properties & Constants

Defines variable data types and intended access permissions.

/** @var string */
private string $name;
Includes & Requires

Documents procedural file imports and dependency inclusion.

/** @var Config */
$config = require 'cfg.php';
Inline Local Variables

Assists IDE static analysis for local variable type resolution.

/** @var \App\User $user */
$user = $container->get('user');

Core Signature Tags (`@param`, `@return`, `@throws`, `@var`)

The primary annotations defining inputs, outputs, exceptions, and property types.

`@param` & `@return` Syntax 
/**
 * Processes incoming order payload.
 *
 * @param  int           $orderId  Unique numeric order identifier.
 * @param  string[]      $items    List of item SKU numbers.
 * @param  bool          $express  Optional express handling flag.
 * @return \App\Response           Processing outcome response object.
 */
public function processOrder(int $orderId, array $items, bool $express = false): Response

Syntax: @param [Type] $[name] [Description] & @return [Type] [Description]

`@throws` & `@var` Annotations 
class Account {
    /**
     * @var \App\Services\LoggerInterface Holds logger reference.
     */
    private $logger;

    /**
     * @param  float $amount
     * @throws \InsufficientFundsException If balance < $amount.
     * @throws \InvalidArgumentException    If $amount <= 0.
     * @return void
     */
    public function withdraw(float $amount): void
}

Multiple `@throws` tags indicate all potential raised exceptions.

PHPDoc Type System BNF Specification

Formal specification of complex types supported in PHPDoc tags according to docs.phpdoc.org/types.html.

Union & Intersection

Combines multiple types using pipe or ampersand syntax:

/** @param string|int|null $id */
/** @param Renderable&Countable $item */
Array Notation (`T[]`)

Denotes an array containing elements of specific type T:

/** @return User[] */
/** @param (User|Account)[] $items */
Array Shapes

Specifies expected associative array keys and value types:

/**
 * @param array{id: int, name: string, email?: string} $user
 */
Generic Collections

Specifies key-value types in generic maps or lists:

/** @return array */
/** @return Collection */
Class Strings

Represents string containing valid class names:

/** @param class-string $class */
/** @return class-string */
Specialized Pseudotypes

Pseudo-types for enhanced static analysis:

/** @param callable-string $func */
/** @param positive-int $count */

Generics & Type Parameters (`@template`, `@extends`)

PHPDoc allows defining type variables using @template for generic classes, functions, and interfaces.

Generic Class & Bounds 
/**
 * @template T of \App\Models\Model
 */
class Repository {
    /** @var array */
    private array $items = [];

    /**
     * @param T $item
     */
    public function add(object $item): void {
        $this->items[] = $item;
    }

    /**
     * @return T
     */
    public function find(int $id): object {
        return $this->items[$id];
    }
}

`T of ClassName` specifies an upper bound for the generic parameter.

Concrete Generic Inheritance 
/**
 * Binds generic parameter T to concrete User class
 *
 * @extends Repository<\App\Models\User>
 * @implements CollectionInterface
 */
class UserRepository extends Repository implements CollectionInterface {
    public function getActiveUsers(): array {
        // IDE knows return type is User[]!
        return array_filter($this->items, fn($u) => $u->isActive());
    }
}

Use @extends, @implements, and @use to pass concrete types to generic parents.

Virtual Members & Magic Methods (`@property`, `@method`, `@mixin`)

Documents dynamic properties and methods handled via magic methods (__get, __call) or class delegation.

`@property` Variations 
/**
 * Dynamic Active Record Entity.
 *
 * @property        int    $id          Read and write magic property.
 * @property-read   string $created_at Read-only magic property.
 * @property-write  string $password   Write-only magic property.
 */
class UserEntity {
    private array $data = [];

    public function __get(string $name) {
        return $this->data[$name] ?? null;
    }
}

Syntax: @property [Type] $[name] [Description]

`@method` & `@mixin` Syntax 
/**
 * Dynamic Query Builder Facade.
 *
 * @method static UserEntity findOrFail(int $id)
 * @method self whereStatus(string $status)
 * @mixin  \App\QueryBuilder
 */
class UserFacade {
    public static function __callStatic($method, $args) {
        return (new QueryBuilder())->$method(...$args);
    }
}

@mixin instructs tools that this class delegates calls to another class.

DocBlock Inheritance & Inline `{@inheritDoc}`

Rules governing how child classes, interfaces, and methods inherit or merge documentation from parent elements.

Inheritance Propagation Rules
  • 1. Automatic Full Fallback: If a method has NO DocBlock, phpDocumentor automatically inherits the complete DocBlock from overridden parent or implemented interface method.
  • 2. Partial Tag Merging: If a method supplies its own DocBlock with tags, `@param` tags are merged by parameter name, and missing tags inherit from parent automatically.
  • 3. Inline Description Augmentation: Use {@inheritDoc} inline inside the description to explicitly inject the parent description text at that exact location.
Augmenting Descriptions via `{@inheritDoc}` 
class BaseService {
    /**
     * Executes fundamental service tasks.
     *
     * @param string $task Identifier.
     */
    public function execute(string $task): void {}
}

class ExtendedService extends BaseService {
    /**
     * {@inheritDoc}
     * Additionally logs execution metrics to Redis.
     */
    public function execute(string $task): void {}
}

Deprecation, Versioning & Lifecycle Annotations

Provides version history, deprecation warnings, author attribution, and licensing metadata.

`@deprecated` 
/**
 * @deprecated 2.4.0 Superseded by
 *   UserResolver::resolve()
 */
function oldGetUser() {}

Flags element as obsolete. IDEs will strike-through method usages.

Syntax: @deprecated [ver] [description]

`@since` & `@version` 
/**
 * @since   1.2.0 Introduced feature.
 * @version 2.1.0 Current release.
 */
class FeatureHandler {}

Tracks element version introduction and current release iterations.

Syntax: @since [ver] [description]

`@author` & `@copyright` 
/**
 * @author    Alex <alex@dev.org>
 * @copyright 2026 Acme Corp
 * @license   MIT
 */

Attributes ownership, copyright holder, and software distribution license.

Syntax: @author Name <email>

API Visibility & Structural Referencing (`@see`, `@link`, `@internal`)

Defines public API boundaries and creates hyperlink cross-references across elements and external URLs.

`@internal` & `{@internal}` Tag 
/**
 * Internal cache serializer.
 *
 * @internal This class is an internal engine implementation detail.
 *   Do not consume directly in external codebases.
 */
class CacheSerializer {
    /**
     * @internal Inline tag to mark {@internal internal logic} block.
     */
    public function serializeRaw(): string {}
}

phpDocumentor hides @internal items unless generated with --parseprivate flag.

`@see` & `@link` Structural References 
/**
 * User authentication service.
 *
 * @see \App\Services\OAuthProvider   Refers to related class FQSEN.
 * @see \App\User::setPassword()       Refers to specific method.
 * @see https://wiki.example.com/auth  Refers to web documentation.
 * @link https://tools.ietf.org/html/rfc6749 OAuth2 Spec.
 */
class AuthService {}

FQSEN = Fully Qualified Structural Element Name (\Namespace\Class::method()).

Programmatic Extraction via PHP Reflection API

How to fetch raw DocComments programmatically at runtime using PHP built-in Reflection reflection classes.

Reading DocComments at Runtime 
$refClass  = new \ReflectionClass(\App\User::class);
$docComment = $refClass->getDocComment();

// Fetching method level DocComment
$refMethod = $refClass->getMethod('findUser');
$methodDoc = $refMethod->getDocComment();

if ($methodDoc !== false) {
    echo "Raw DocComment:\n" . $methodDoc;
} else {
    echo "No DocComment attached or stripped by OPcache!";
}

Returns raw unparsed string or `false` if missing.

Critical Production OPcache Caveat

By default in production, PHP OPcache might strip comments to save bytecode memory if opcache.save_comments=0 is set in php.ini.

If comments are stripped, getDocComment() will return false! Frameworks relying on PHPDoc annotations (like Doctrine or Symfony) require:

opcache.save_comments=1

Source: docs.phpdoc.org

Parsing DocBlocks via `phpdocumentor/reflection-docblock`

Programmatically converting raw DocComment strings into structured object AST using the official parser library.

DocBlockFactory AST Parsing 
use phpDocumentor\Reflection\DocBlockFactory;

$factory  = DocBlockFactory::createInstance();
$docBlock = $factory->create($rawDocCommentString);

// Programmatic AST Accessors
$summary     = $docBlock->getSummary();     // string
$description = $docBlock->getDescription(); // Description object
$tags        = $docBlock->getTags();        // Tag[] array

// Querying specific tags programmatically
$paramTags = $docBlock->getTagsByName('param');
foreach ($paramTags as $param) {
    /** @var \phpDocumentor\Reflection\DocBlock\Tags\Param $param */
    echo $param->getVariableName(); // "identifier"
    echo $param->getType();         // "string"
}

Package: composer require phpdocumentor/reflection-docblock

AST Object Hierarchy Structure
DocBlock Object
├── getSummary(): string
├── getDescription(): Description
└── getTags(): TagInterface[]
Tag Objects (`Param`, `Return`, `Var`, `Throws`)
├── getName(): string ("param")
├── getType(): Type ("string|int")
└── getDescription(): Description
